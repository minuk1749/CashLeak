# CashLeak

매달 조용히 빠져나가는 정기 구독을 찾아 정리하는 서비스입니다.
은행·카드 거래내역과 Gmail·네이버메일 영수증을 함께 보고, 사용자가 직접 등록하지 않아도 구독 목록과 다음 결제일을 만들어 줍니다.

## 진행 상황

1. **탐지 검증**: 탐지 엔진을 가상 데이터로 검증 완료. 실제 거래내역·메일로 검증하는 일이 남아 있습니다.
2. 웹앱 기본 틀: Next.js + Supabase, 로그인, 파일 업로드, 구독 목록, 수동 수정
3. 교차검증 연결: 앱에서 메일(IMAP) 수집과 거래내역 탐지 결과를 연결
4. 배포와 마무리

아래는 1단계에서 만든 탐지 엔진 설명입니다.

## 하는 일

1. **거래내역 정리**: 카드대금, 적금·투자 이체, 현금 인출은 분석에서 빼고, 통장과 카드 내역에 둘 다 찍힌 체크카드 결제는 하나만 셉니다.
2. **반복 결제 찾기**
   - 가맹점명을 정규화해 같은 곳끼리 묶습니다 (뒤에 붙는 승인번호, `(주)` 같은 표기 제거, 알려진 서비스는 별칭으로 통일).
   - 같은 기준일 ±3일에 한 달(또는 1년) 간격으로 결제됐는지 봅니다. 31일 결제가 짧은 달에 말일로 당겨지는 것, 주말·공휴일로 밀리는 것도 처리합니다.
   - 애플(`APPLE.COM/BILL`)처럼 한 가맹점에 구독이 여러 개면 금액별로 나눕니다. 해외 결제는 원화가 아니라 달러 금액으로 비교합니다.
   - 가격이 한 번 오르면 같은 구독의 가격 변경으로 기록하고, 통신비처럼 매달 금액이 다른 자동이체도 찾습니다.
   - 예정일이 지나도 결제가 없으면 해지로 추정합니다.
3. **메일 영수증 읽기**
   - 발신 도메인으로 서비스를 식별합니다 (비슷한 주소의 피싱 메일은 무시).
   - 제목·금액 줄·상품명 줄·갱신일 중 하나에 구독 표현이 있어야 영수증으로 봅니다 (일반 주문 메일 제외).
   - 금액(원·달러), 주기, 다음 결제일을 뽑고, 두 메일함에 같은 영수증이 있으면 하나만 남깁니다.
4. **교차검증**
   - 거래와 영수증을 금액과 날짜(±3일)로 짝지어, 애플·구글·네이버페이·결제대행사로 찍힌 결제가 실제로 어떤 서비스인지 확정합니다.
   - 해지 메일이 있으면 "해지 확인", 연간 결제처럼 거래가 한 번뿐인 구독은 영수증으로 보완합니다.
5. **신뢰도**: 반복 횟수, 금액 안정성, 알려진 서비스인지, 메일로 확인됐는지, 같은 곳에서 다른 결제가 많은지(우연일 가능성)를 합쳐 높음·보통·낮음으로 표시합니다.

## 실행

Node.js 22.18 이상이 필요합니다 (TypeScript 파일을 바로 실행). 실행에 필요한 외부 패키지는 없습니다.

```bash
npm install          # 타입 검사용 typescript만 설치됨
npm run generate     # data/sample 에 데모 사용자 데이터 생성
npm run detect       # 탐지 결과 → out/result.md, out/result.json
npm run evaluate     # 가상 사용자 200명으로 정확도 평가 → out/evaluation.md
npm test             # 단위 테스트
npm run typecheck
```

다른 데이터로 돌리려면 폴더에 `bank*.csv`(통장), `card*.csv`(카드), `emails-*.json`(메일)을 넣고 `node scripts/detect.ts <폴더>` 를 실행합니다.
실제 개인 데이터는 `data/private/` 에 두세요. 이 폴더는 git에 올라가지 않습니다.

## 구조

```
src/                 앱(2단계)에 그대로 옮겨 쓸 탐지 엔진
  types.ts           공통 타입 (거래, 메일, 영수증, 구독)
  merchants.ts       서비스 카탈로그, 가맹점 정규화, 제외 규칙
  detect/            반복 결제 탐지, 체크카드 중복 제거
  email/parse.ts     메일 영수증 파서 (규칙 기반)
  match/             거래와 영수증 교차검증, 신뢰도
  io/                CSV 읽기, 은행·카드 내역 가져오기
  pipeline.ts        전체 흐름
  report.ts          결과 마크다운
sim/                 가상 데이터 생성기와 채점 (평가용)
scripts/             generate / detect / evaluate
test/                단위 테스트
data/sample/         데모 사용자 데이터와 정답(truth.json)
```

## 가상 데이터 결과

데모 사용자(구독 16개, 함정 데이터 포함)는 찾을 수 있는 15개를 모두 찾았고, 데이터에 흔적이 1건뿐인 티빙만 놓쳤습니다. 실행 결과 예시는 [docs/step1-sample-result.md](docs/step1-sample-result.md), 평가 전체 결과는 [docs/step1-evaluation.md](docs/step1-evaluation.md)에 있습니다.

무작위 가상 사용자 300명 평가 (`npm run evaluate -- 300`):

| 지표 | 값 |
|---|---|
| 재현율 (찾을 수 있는 구독 기준) | 100% |
| 재현율 (전체, 흔적이 부족한 구독 포함) | 95.1% |
| 정밀도 (이용 중 + 신뢰도 보통 이상, 앱에서 확정으로 보여줄 목록) | 100% |
| 정밀도 (해지 추정, 신뢰도 낮음까지 전체) | 98.3% |
| 금액 / 주기 / 상태 정확도 | 100% / 100% / 100% |
| 다음 결제일 (±3일 / 정확히 일치) | 100% / 98.2% |

오탐 35건은 모두 편의점·서점에서 우연히 같은 금액이 한 달 간격으로 반복된 경우이고, 전부 신뢰도 "낮음"이나 "해지 추정"으로 분류됐습니다.

## 한계

- **이 숫자는 실제 정확도가 아닙니다.** 가상 데이터와 탐지 규칙을 같은 사람이 만들었으므로, 설계한 경우들을 제대로 처리한다는 확인일 뿐입니다.
- 실제 토스·은행·카드사 내보내기 파일 형식은 아직 확인하지 못했습니다. 머리글 이름으로 열을 찾게 해 두었지만 실제 파일을 받으면 형식별로 맞춰야 합니다.
- 메일 파서는 규칙 기반이라 가상 템플릿에 맞춰져 있습니다. 실제 메일은 형식이 다양해서 LLM 파서로 보완할 계획입니다.
- 서비스 카탈로그는 16개뿐입니다. 카탈로그에 없는 가맹점도 반복 패턴으로 찾지만 이름은 가맹점명 그대로 나옵니다.
- 결제 1건에 메일도 없으면 원리상 찾을 수 없습니다. 새 구독은 두 번째 결제부터, 자주 가는 가게의 구독은 세 번째 결제부터 잡힙니다.
- 연간 구독은 데이터 기간(6개월) 안에 결제나 갱신 안내 메일이 없으면 찾을 수 없습니다. 평가에서 Microsoft 365 116건 중 53건이 이 경우였습니다.
